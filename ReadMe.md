# Wuwa Tappo 寶箱助手

Windows 桌面工具：啟動時辨識 Wuwa Tappo 計數器，再用鍵盤／滑鼠輸入偵測更新估算值，定期校正。用冷門按鍵補足次數後，自動點擊金色寶箱並等待 30 分鐘冷卻。

## 使用方式

1. 首次使用，安裝含 Tkinter、pip 與 `py` 啟動器的 Python 3.11 以上版本，再雙擊 `Setup.bat`。
2. 開啟 Wuwa Tappo，讓桌寵、計數器及寶箱保持可見。
3. 雙擊 `Start.bat`，在 Windows 使用者帳戶控制（UAC）提示中允許管理員權限；取消授權就不會啟動。若已用管理員身分執行則直接啟動。工具啟動時預設暫停；關掉啟動它的 Terminal 後仍可執行。
4. 分別勾選「自動按鍵」與「自動領取寶箱」。選擇累積按鍵、寶箱數、每秒次數，修改後按「套用並暫停」。
5. 按 **F5** 或「開始」啟動；再按一次 F5 即暫停。
6. 關閉寶箱助手視窗即可結束程式。

| 設定／控制 | 說明 |
| --- | --- |
| F5 | 開始／暫停，唯一的全域控制快捷鍵 |
| 自動按鍵 | 開啟後持續送出所選按鍵，達標或領箱冷卻都不會停止此功能 |
| 自動領取寶箱 | 只控制領箱，須符合實際計數門檻且冷卻完成 |
| F7～F9 | 保留給 Wuwa Tappo |
| 累積按鍵 | 可選 F13～F24；首次使用預設 F13 |
| 寶箱數 | 1 個需要 1000 次；2 個需要 2000 次 |
| 每秒次數 | 可選 1～10，預設最多每秒 5 次；送鍵獨立於畫面辨識執行 |
| 測試 20 次 | 只送出 20 次所選按鍵，完成自動暫停，不領寶箱 |

F6 與 Esc 沒有綁定工具功能。若 F5 被其他程式占用，可用介面中的開始／暫停按鈕。累積鍵會送到目前前景程式，請選未被其他程式綁定的 F13～F24。

## 依實際計數執行

介面分開顯示 **「Wuwa Tappo 辨識值」** 與 **「含輸入估算」**。前者來自畫面辨識；後者在該讀值上加上之後偵測到的鍵盤與滑鼠按下次數，包含你平常操作與工具自動送出的輸入。工具不以自己已送出的按鍵次數代替遊戲計數。

```text
F5 總開關
├─ 自動按鍵：依開關持續送鍵
└─ 自動領箱：混合估算與 OCR 確認達標 → 點擊寶箱 → 冷卻 30 分鐘
```

- 以 Windows 內建 OCR 辨識計數器，兩種影像處理結果必須相同；定位按灰階形狀處理，不依賴星星的紫色或黑色底色。
- 辨識不到或有歧義時會停止領箱、保留開始狀態，隔 2～10 秒自動重試。自動按鍵依獨立開關持續，不因 OCR 失敗而關閉。若你按 F5 手動暫停，恢復辨識也不會自行開始。
- 啟動與恢復時讀取一次，平常約每 30 秒校正；估算達標且看到可點擊寶箱時，會先重新辨識才領取。領取後也會提早校正，不會每次輸入都做 OCR。
- 自動按鍵使用獨立執行緒，畫面擷取、OCR 與診斷存檔不會阻塞正常送鍵；F5 暫停仍立即生效。實際速率仍受修飾鍵、桌面狀態及系統排程影響。
- 輸入偵測只保留鍵盤／滑鼠累積數量與暫時的按下狀態，不儲存輸入文字或按鍵歷史。鍵盤自動重複不重複計數；估算誤差由畫面辨識校正。
- 只擷取 Wuwa Tappo 主視窗範圍來定位。它的透明主視窗目前鋪滿所在螢幕，定位後會改擷取計數器與寶箱的小範圍；桌寵移動或定位失敗時才重新定位。擷取不包含其他螢幕，也不先複製整個虛擬桌面。
- 輸入估算達到門檻時仍須重新辨識才允許領箱；自動按鍵可獨立持續。若輸入偵測無法使用，會暫改為較頻繁的畫面校正。
- Ctrl、Shift、Alt、Windows 鍵或滑鼠按鈕按住時暫緩送鍵；找不到唯一桌寵視窗時不送鍵。
- 寶箱點擊前需鍵盤／滑鼠閒置至少 1.2 秒、位置穩定且確實位於桌寵的主視窗或同程序 `DesktopCatInput` 輸入層。
- 助手啟動時會要求管理員權限，以配合 Wuwa Tappo 的管理員模式；領箱前仍會檢查 Windows 輸入權限。遊戲權限高於助手時，會暫停領箱並保留原因提示；可用的全域自動按鍵仍依開關持續。若仍有舊的一般權限助手開著，請先關閉，再執行 `Start.bat` 並允許管理員權限。
- 第二個寶箱若暫時看不到，保留領取進度並重試；超過 45 秒仍未確認會暫停，按 F5 可再試。
- 已確認的寶箱數與冷卻會存檔，關閉重開仍可接續；再次啟動不會建立第二個送鍵程序。
- 冷卻只限制領箱，自動按鍵依開關持續。準備點擊已達標、可見的寶箱時會短暫停止自動送鍵，讓鍵鼠達到 1.2 秒閒置條件。內部診斷用的按鍵數不影響領取門檻。

目前以所選的整組寶箱為冷卻單位，沒有分別追蹤每個寶箱的遊戲內倒數。圖案消失代表畫面辨識結果改變，未直接驗證帳號獎勵入帳。

OCR 完全在本機執行，不會上傳畫面，也不直接呼叫遊戲領獎 API。使用的是 [Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine) 與 [PyWinRT](https://pywinrt.readthedocs.io/en/latest/installing/) 介面，需有 Windows 英文或中文 OCR 語言功能。

## 安裝與除錯指令

在專案資料夾執行 PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\Start.bat
```

要在 Terminal 內查看除錯資訊，請先以管理員身分開啟 PowerShell，再執行下列指令；此模式會依附 Terminal。一般權限執行會先要求 UAC 授權並另開管理員程序：

```powershell
.\.venv\Scripts\python.exe main.py
```

離線辨識寶箱圖片，不會產生輸入，也不需要管理員權限：

```powershell
.\.venv\Scripts\python.exe main.py --detect-image assets/chest_example.png
```

執行測試：

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

測試會替換鍵盤／滑鼠輸入，涵蓋依實際計數達標、OCR 歧義與遮擋、暫停續跑、第二個寶箱位置變動、冷卻、輸入層視窗驗證、單一實例與快捷鍵。Windows OCR 的測試會讀取專案內的小型範本，不操作桌面。

目前 115 項測試通過，包含獨立功能開關、OCR 阻塞期間持續送鍵與暫停、領箱等待閒置時維持停鍵、短測試途中套用設定、存檔衝突重試、Windows 輸入權限與 token 資源釋放、滑鼠接管、局部擷取、黑／紫星星外觀、自動恢復與資源釋放。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `main.py` | 介面、實際計數驅動流程、領取與冷卻 |
| `counter_reader.py` | 計數器定位與 Windows OCR |
| `input_monitor.py` | 只統計鍵盤／滑鼠操作數量的輸入偵測 |
| `capture.py` | 只複製指定局部範圍的畫面擷取 |
| `detector.py` | 寶箱及計數器圖案比對 |
| `windows_api.py` | 輸入、視窗驗證、F5 與單一實例鎖 |
| `Start.bat`、`Launch.pyw`、`startup.py` | 管理員授權、脫離 Terminal 的啟動及錯誤提示 |
| `Setup.bat`、`requirements.txt` | 建立環境及安裝套件 |
| `assets/chest_*.png`、`assets/counter_*.png` | 辨識範本與離線測試素材 |
| `test_*.py` | 自動化測試 |
| `runtime.json` | 執行時產生的設定、領取進度及冷卻時間 |
| `clicker.log`、`startup.log` | 執行與啟動失敗紀錄 |

按鍵診斷約每兩秒批次保存，暫停或正常結束時會再保存一次；突然中斷可能少記最後約兩秒的診斷次數，不影響依畫面判斷的領箱門檻。領取進度與冷卻仍即時保存；Windows 短暫鎖住檔案時會重試，診斷寫入失敗則留待下次保存。若點擊後突然結束、尚未確認結果，會保留保守的冷卻截止時間，避免立即重複點擊。

## 常見狀況

| 狀況 | 處理 |
| --- | --- |
| 計數顯示「辨識中／不可見」 | 讓計數器完整露出；已開始時會自動重試並接續，不必反覆按 F5。 |
| 遊戲計數沒有增加 | 先用「測試 20 次」確認；可換另一個 F13～F24 再試。 |
| 寶箱被其他視窗遮住 | 移開覆蓋寶箱的視窗。 |
| 第二個寶箱未確認 | 進度會保留；檢查寶箱與計數，再按 F5 重試。 |
| 提示遊戲權限高於助手 | 關閉舊助手，再執行 `Start.bat` 並允許管理員權限。 |
| 外觀或縮放改變後讀不到 | 範本取自 Wuwa Tappo v1.0.4；外觀改版可能需要更新辨識範本。 |
| 啟動失敗 | 查看錯誤提示及 `startup.log`，必要時重新執行 `Setup.bat`。 |
| 提示工具已在執行 | 使用已開啟的工具視窗；只允許同一專案啟動一個實例。 |
