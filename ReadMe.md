# WuwaTappo Helper

Windows 桌面工具：以鍵盤／滑鼠輸入累積為主要點擊估算，定期用 Wuwa Tappo 畫面計數校正。用冷門按鍵補足次數後，自動點擊金色寶箱並等待 30 分鐘冷卻。

主面板集中顯示主要點擊數、執行狀態、冷卻與已確認寶箱。右上角的太陽／月亮圖示切換淺色與深色模式，「EN／中」切換中文與 English，選擇會自動保存；外框、控制項與選單同步配色，原生標題列不顯示名稱。前台／背景採雙選項切換；設定變更即套用，不需要額外確認按鈕。

## 使用方式

1. 首次使用，安裝含 Tkinter、pip 與 `py` 啟動器的 Python 3.11 以上版本，再雙擊 `Setup.bat`。
2. 開啟 Wuwa Tappo。計數辨識直接擷取其透明視窗，可在其他視窗遮擋時計數；實際點擊寶箱仍需寶箱保持可見。
3. 雙擊 `Start.bat`，在 Windows 使用者帳戶控制（UAC）提示中允許管理員權限；取消授權就不會啟動。若已用管理員身分執行則直接啟動。工具啟動時預設暫停；關掉啟動它的 Terminal 後仍可執行。
4. 分別勾選「自動按鍵」與「自動領箱」。選擇累積按鍵、每秒次數及寶箱點擊方式；選項變更會直接套用並保存，保持原本的開始／暫停狀態。主面板不再提供寶箱數設定與短測試按鈕。
5. 按「開始」啟動，按「暫停」停止；不註冊 F5 或其他全域控制快捷鍵。
6. 關閉寶箱助手視窗即可結束程式。

| 設定／控制 | 說明 |
| --- | --- |
| 開始／暫停 | 由視窗按鈕控制，不使用全域控制快捷鍵 |
| 自動按鍵 | 開啟後持續送出所選按鍵，達標或領箱冷卻都不會停止此功能 |
| 自動領取寶箱 | 只控制領箱，須符合輸入估算門檻、畫面上有可領寶箱且冷卻完成 |
| F7～F9 | 保留給 Wuwa Tappo |
| 累積按鍵 | 可選 F13～F24；首次使用預設 F13 |
| 每秒次數 | 可選 1～10，預設最多每秒 5 次；送鍵獨立於畫面辨識執行 |
| 寶箱點擊方式 | 「前台」或「背景」；旁邊的 ⓘ 可顯示滑鼠使用提醒 |
| 太陽／月亮 | 切換淺色／深色並自動保存；不改變執行狀態 |
| EN／中 | 即時切換按鈕、狀態與提示的語言並自動保存；不改變計數與冷卻 |

工具不綁定全域控制快捷鍵。累積鍵會送到目前前景程式，請選未被其他程式綁定的 F13～F24。鍵盤／滑鼠分類仍在內部計數，但不顯示於主面板。

## 前台與背景領箱

- **前台**：保留原有方式，等待鍵鼠閒置至少 1.2 秒後，將系統游標移到寶箱，送出點擊，再視情況移回原位。助手不主動將遊戲切成前景，但會暫時使用你的游標。
- **背景**：直接向同一遊戲程序中、寶箱位置的主視窗或 `DesktopCatInput` 輸入視窗送出滑鼠訊息。不移動系統游標、不主動切換前景，也不等待鍵鼠閒置；兩種模式都會短暫停送自動按鍵以核對領取結果。
- 背景模式仍使用螢幕辨識，**寶箱須保持可見**；不支援最小化或被其他視窗遮住。計數器改用指定視窗擷取，其他視窗遮擋不影響 OCR；視窗本身最小化、關閉或不再繪製時不使用舊影格。暫時無法校正不影響健康的輸入偵測繼續累積。它只改變領箱方式，自動累積按鍵仍是全域輸入。
- 背景模式是否有效取決於遊戲是否處理視窗訊息。訊息成功送出不代表成功領箱；兩種模式都以寶箱圖案消失確認畫面變化，再從主要估算扣除每箱 1000 次，後續 OCR 可進一步校正。
- 背景未確認時會提示並暫停領箱，保留保守冷卻；**不會自動改用前台**。切換方式直接套用，保留開始／暫停狀態、進度、功能開關與冷卻；已排程但尚未送出的舊設定點擊會取消，已送出的點擊仍會確認結果。切換本身不會強制再領一次。
- 兩種模式都沿用啟動時的管理員授權，以及領箱前的權限、程序身分、位置與遮擋檢查。

背景訊息使用 Windows 的 [PostMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)，以 [ScreenToClient](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-screentoclient) 換算指定視窗座標；不注入遊戲程序，也不呼叫遊戲網路介面。

## 輸入累積與 OCR 校正

介面顯示 **「主要點擊數」**，內部以最後一次校正為基準，加上後續偵測到的鍵盤與滑鼠按下次數，包含日常操作與工具自動送出的輸入。數字仍屬輸入估算，由背景 OCR 校正；校正值與詳細使用說明不顯示在主面板。

尚未成功校正且沒有新輸入時，顯示「讀取中」而非 0；內部從本次啟動的零基準開始累積，不猜測遊戲原有點擊數。首次成功 OCR 會帶入遊戲原有點數。重新開啟會重新建立計數基準；設定、已領進度與冷卻則會保留。每次畫面確認領箱後先扣除 1000，再校正，避免重複扣除。

```text
視窗開始／暫停按鈕
├─ 自動按鍵：依開關持續送鍵
└─ 自動領箱：輸入估算達標＋可領寶箱可見 → 點擊 → 確認圖案消失並扣除估算 → 冷卻
```

- 以 Windows 內建 OCR 校正計數器，兩種影像處理結果必須相同，不把英文字母猜成數字。先篩選棕色數字，減少桌寵紅白腳部的干擾；整個數字被遮住仍拒絕校正。
- OCR 辨識不到或有歧義時保留估算，隔 2～10 秒自動重試，不因單次校正失敗中斷領箱。若你手動暫停，辨識恢復也不會自行開始。
- 啟動與恢復時嘗試校正，平常約每 30 秒一次；領取後會提早校正。領箱前不再強制重新讀取 OCR。
- 自動按鍵使用獨立執行緒，畫面擷取、OCR 與診斷存檔不會阻塞正常送鍵；暫停會立即停止後續輸入。實際速率仍受修飾鍵、桌面狀態及系統排程影響。
- 輸入偵測只保留鍵盤／滑鼠累積數量與暫時的按下狀態，不儲存輸入文字或按鍵歷史。鍵盤自動重複不重複計數；估算誤差由畫面辨識校正。
- 使用 Windows Graphics Capture 精確指定 Wuwa Tappo 的 HWND，取得透明視窗本身的畫面，不再截取桌面可見像素。每次需要辨識時建立新擷取、取得新影格後停止，不常駐錄影或回用舊影格。定位後只複製計數器與寶箱的局部像素到 CPU；視窗尺寸、程序或身分改變會拒絕該影格並重試。擷取失敗不偷偷退回桌面截圖。
- 輸入偵測無法使用時不沿用失效的輸入增量，暫改為較頻繁的 OCR 校正；只有五秒內成功且尚未失敗的校正可允許領箱。找不到唯一遊戲視窗時也不送出輸入。
- Ctrl、Shift、Alt、Windows 鍵或滑鼠按鈕按住時暫緩送鍵；找不到唯一桌寵視窗時不送鍵。
- 前台模式點擊前需鍵盤／滑鼠閒置至少 1.2 秒；背景模式跳過閒置等待。兩種模式都需要位置穩定且確實位於桌寵的主視窗或同程序 `DesktopCatInput` 輸入層。
- 助手啟動時會要求管理員權限，以配合 Wuwa Tappo 的管理員模式；領箱前仍會檢查 Windows 輸入權限。遊戲權限高於助手時，會暫停領箱並保留原因提示；可用的全域自動按鍵仍依開關持續。若仍有舊的一般權限助手開著，請先關閉，再執行 `Start.bat` 並允許管理員權限。
- 第二個寶箱若暫時看不到，保留領取進度並重試；超過 45 秒仍未確認會暫停，按暫停後再開始可重試。
- 已確認的寶箱數與冷卻會存檔，關閉重開仍可接續；再次啟動不會建立第二個送鍵程序。
- 冷卻只限制領箱，自動按鍵依開關持續。準備點擊已達標、可見的寶箱時會短暫停止自動送鍵；前台模式另外等待 1.2 秒閒置。內部診斷用的按鍵數不影響領取門檻。

目前以所選的整組寶箱為冷卻單位，沒有分別追蹤每個寶箱的遊戲內倒數。圖案消失代表畫面辨識結果改變，未直接驗證帳號獎勵入帳。背景模式已有一次實機領箱的圖案消失確認；30 分鐘完整等待尚未在此次測試驗證。

OCR 完全在本機執行，不會上傳畫面，也不直接呼叫遊戲領獎 API。使用的是 [Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine) 與 [PyWinRT](https://pywinrt.readthedocs.io/en/latest/installing/) 介面，需有 Windows 英文或中文 OCR 語言功能。

視窗擷取使用 [windows-capture 2.0.1](https://github.com/NiiightmareXD/windows-capture)，與 [OBS 的 WGC 擷取](https://github.com/obsproject/obs-studio/blob/master/libobs-winrt/winrt-capture.cpp) 同類。新環境請先執行 Setup.bat 安裝相依套件。

## 安裝與除錯指令

在專案資料夾執行 PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\Start.bat
```

要在 Terminal 內查看除錯資訊，請先以管理員身分開啟 PowerShell，再執行下列指令；此模式會依附 Terminal。一般權限執行會先要求 UAC 授權並另開管理員程序：

```powershell
.\.venv\Scripts\python.exe -m wuwa_helper
```

離線辨識寶箱圖片，不會產生輸入，也不需要管理員權限：

```powershell
.\.venv\Scripts\python.exe -m wuwa_helper --detect-image assets/chest_example.png
```

執行測試：

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

測試會替換鍵盤／滑鼠輸入，涵蓋前後台切換與保存、背景訊息定址與取消、輸入估算與 OCR 校正、未確認點擊的狀態保存，以及管理員啟動。Windows OCR 的回歸測試會讀取專案內的小型範本，不操作桌面。實際項目數以測試輸出為準。


## 檔案

| 檔案 | 用途 |
| --- | --- |
| `wuwa_helper/main.py` | 介面、輸入估算、領取與冷卻 |
| `wuwa_helper/counter_reader.py` | 計數器定位與 Windows OCR 校正 |
| `wuwa_helper/input_monitor.py` | 只統計鍵盤／滑鼠操作數量的輸入偵測 |
| `wuwa_helper/window_capture.py` | 指定透明視窗的 Windows Graphics Capture、影格驗證與資源釋放 |
| `wuwa_helper/capture.py` | 舊桌面局部擷取，僅保留供對照診斷 |
| `wuwa_helper/detector.py` | 寶箱及計數器圖案比對 |
| `wuwa_helper/windows_api.py` | 前後台輸入、視窗驗證與單一實例鎖 |
| `wuwa_helper/themes.py`、`wuwa_helper/window_style.py` | 淺深色配色、原生標題列、邊框與圓角 |
| `wuwa_helper/i18n.py` | 中文與 English 介面文字、執行訊息翻譯 |
| `wuwa_helper/startup.py`、`Start.bat`、`Launch.pyw` | 管理員授權、脫離 Terminal 的啟動及錯誤提示 |
| `wuwa_helper/paths.py` | 根目錄資源與狀態路徑；從其他工作目錄啟動也不改變 |
| `main.py` | 相容舊指令的薄入口；主要實作位於 `wuwa_helper/` |
| `Setup.bat`、`requirements.txt` | 建立環境及安裝套件 |
| `assets/chest_*.png`、`assets/counter_*.png` | 辨識範本與離線測試素材 |
| `tests/` | 自動化測試 |
| `scripts/diagnose_counter.py` | 唯讀計數器診斷，不送出輸入 |
| `scripts/preview_ui.py` | 使用示範數字與暫存設定的外觀預覽，不擷取或操作遊戲 |
| `runtime.json` | 執行時產生的設定、領取進度及冷卻時間 |
| `clicker.log`、`startup.log` | 執行與啟動失敗紀錄 |

按鍵診斷約每兩秒批次保存，暫停或正常結束時會再保存一次；突然中斷可能少記最後約兩秒的診斷次數，不影響依畫面判斷的領箱門檻。領取進度與冷卻仍即時保存；Windows 短暫鎖住檔案時會重試，診斷寫入失敗則留待下次保存。若點擊後突然結束、尚未確認結果，會保留保守的冷卻截止時間，避免立即重複點擊。

## 常見狀況

| 狀況 | 處理 |
| --- | --- |
| 提示 OCR 暫時無法校正 | 確認遊戲視窗未最小化且計數器本身正在繪製；主要點擊數仍會累積。查看 clicker.log 的 Counter calibration unavailable 可區分擷取、定位、遮擋及 OCR 文字問題。 |
| 遊戲計數沒有增加 | 確認「自動按鍵」已開啟且助手正在執行；可換另一個 F13～F24 再試。 |
| 寶箱被其他視窗遮住 | 移開覆蓋寶箱的視窗。 |
| 第二個寶箱未確認 | 進度會保留；檢查寶箱與計數，按暫停後再開始重試。 |
| 提示遊戲權限高於助手 | 關閉舊助手，再執行 `Start.bat` 並允許管理員權限。 |
| 外觀或縮放改變後讀不到 | 範本取自 Wuwa Tappo v1.0.4；外觀改版可能需要更新辨識範本。 |
| 啟動失敗 | 查看錯誤提示及 `startup.log`，必要時重新執行 `Setup.bat`。 |
| 提示工具已在執行 | 使用已開啟的工具視窗；只允許同一專案啟動一個實例。 |

## 視窗擷取診斷

```powershell
.\.venv\Scripts\python.exe scripts/diagnose_counter.py
.\.venv\Scripts\python.exe scripts/diagnose_counter.py --backend screen
```

第一個指令使用新的視窗擷取；第二個保留舊桌面擷取作對照。兩者均不送出鍵鼠輸入，僅將計數器局部影像存至 diagnostics/。
